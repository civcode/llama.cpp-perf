# Report 0037 — stopped at preflight GPU fault

**Status: Blocked.** Starting commit `840d02efe86c4533d93834bb9e09740e02962677`. A current-boot AMD GPU page/protection-fault burst was discovered during passive preflight. Per the stop rule, no GPU fixture, profiler or model workload was launched in this iteration; there was no four-condition experiment, numerical comparison or stage-correlated NVIDIA timing. The fault predated this turn's preflight and the journal names a different process; this is not evidence that the candidate attention kernel caused it. Its cause and resolution are unknown.

## Build and concrete compilation limitation

The mixed CUDA sm_89 / HIP gfx1201 Release `llama-server` and `test-backend-ops` build completed on the starting source; the standalone C++ request test and 215 focused Python QSA tests passed. The pinned UI download fell back to `latest`, a build-provenance caveat. **This build does not prove the new specialization compiled.** Inspection of `libggml-hip.so` using `nm -C` found the ordinary `<256,256,4,4,...,true,false>` sparse kernel but zero `<256,256,4,4,false,false,true,true>` FP32 symbols. The host dispatch in `fattn-mma-f16.cuh` is guarded by `GGML_USE_HIP && AMD_WMMA_128B_AVAILABLE`, an architecture-specific macro; the observed host symbol absence is consistent with that branch being excluded in host compilation. The exact host/device compilation guard and resulting candidate device instantiation need correction and verification; a successful mixed build alone is not proof of FP32 code generation.

Restored an explicit fail-closed abort for a valid FP32 request in `ggml/src/ggml-cuda/fattn.cu`, since the candidate is neither actually instantiated nor validated. Invalid requests still abort, and flag-unset behavior remains unchanged. Rebuilt the mixed targets successfully after that safety change using `-j 28`; this was compilation/linking only, not GPU execution. The source candidate remains for further work, but no actual F32 attention symbol, mapped-loader fixture, arithmetic correctness, occupancy or trace is established. The proposed path also retains the documented F16 shared-memory cast after FP32 register accumulation and rescaling.

## Safety and timing evidence

At 14:12:40 local time on Nov 13, current-boot kernel logs show repeated AMD gfxhub page faults, including permission and mapping fault status, attributed by the kernel to process `strata`. Preflight inspection was around 14:35 local time, after the build; the device fault therefore predates our preflight and no GPU task was started by this iteration. The read-only journal window is preserved externally at `iteration-0037/kernel-fault-window.log`. The preflight snapshot immediately before discovery reported NVIDIA current PCIe Gen1, maximum Gen3 and 15930 MiB free; both AMD gfx1201 devices were enumerated. This idle snapshot does not prove loaded Gen3 or rule out link/power transients. There was no GPU retry, reset, reboot, driver/PCIe/power change, stress test or GitHub Actions.

No condition-stage timing exists because the pilot was not run. As stated in Handoff 0037, the first prior Xid79/154 pair occurred during fourth-task CUDA prefill with HIP tracing active; the second pair's active application/tracer state is unknown. Neither the prior reports nor this blocked attempt establish a workload-timing cause. A later CUDA synchronization failure need not identify the originating asynchronous operation. Sampling and tracing themselves may perturb scheduling; even an eventual clean pilot cannot exclude intermittent PCIe, power or timing faults.

Next work requires operator resolution of the current-boot device-health concern and authorization to resume GPU activity, then correct the host/device specialization guard, rebuild and inspect the real FP32 device symbol, validate the actual ldmatrix operands and half-output combine on both GPUs, prove layer11 trace/negative controls, and only then perform the already-bounded pilot with its synchronized telemetry. No model output, tensor or new profiler trace was produced.
