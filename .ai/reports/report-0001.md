## Trace and callsite findings

The analyzer ran unchanged on the original short trace; all three fixture tests passed. In the 6.000-9.371 s window, 3,981 `hipStreamSynchronize` calls on one thread totaled 2,769.2 ms (82.15% of the window), mean 695.6 us, p95 7.806 ms. Of these, 2,698 have immediate neighbors `hipMemcpyAsync -> sync -> hipEventSynchronize` and account for only 135.0 ms; 129 `hipMemcpyAsync -> sync -> sync` and 254 `sync -> sync -> sync` account for 997.5 and 1,418.9 ms respectively. Neighbor patterns do not establish callsites.

A separate short target-only `tg128` run interposed `hipStreamSynchronize` to collect backtraces and durations without inserting synchronization. Of the timed-generation calls, 256 calls taking 2,005.1 ms originate at `test_gen`'s explicit per-token `llama_synchronize` (`tools/llama-bench/llama-bench.cpp`), through `llama_context::synchronize`, `ggml_backend_sched_synchronize`, and `ggml_backend_cuda_synchronize`. This waits on both HIP backends and their outstanding work; it does not establish redundant waiting. Another 3,200 calls taking 245.4 ms originate in `ggml_backend_cuda_buffer_set_tensor` during scheduler graph execution, and 256 calls taking 56.9 ms go through `ggml_backend_tensor_copy` to the same set-tensor path. These are separate-run observations, not stack attribution of the original trace. Instrumented and uninstrumented short runs measured 46.52 and 46.51 t/s respectively, one run each; this is not a rigorous overhead bound. The first interposer attempt crashed because the HIP library was locally loaded; resolving its handle explicitly fixed the diagnostic. The reference build was not modified.

The original trace's 128 agent-2-to-host copies of 993,280 bytes match exactly 248,320 vocabulary entries times four bytes; the verbose model log confirms that vocabulary size and `src/llama-context.cpp` has that logits readback size. This strongly supports logits but does not prove each copy's tensor identity. GPU kernel times and API wait times overlap and must not be summed as elapsed time; the HIP trace excludes NVIDIA activity.

## Recommendation and limits

Prioritize measuring whether the 25 per-token synchronous host-to-device set-tensor calls can be safely batched or made asynchronous with correct host-buffer lifetime and stream/event dependencies. First attribute their tensors, bytes, streams and true critical-path contribution with opt-in counters in a separate build; compare end-to-end performance and finite outputs/GDN state at short and long context before changing scheduling. The larger benchmark wait chiefly includes completion of outstanding work; removing it is not an established optimization, and benchmark synchronization behavior must not be assumed identical to MTP server sampling. No scheduling prototype or MTP trace was attempted without that evidence.
