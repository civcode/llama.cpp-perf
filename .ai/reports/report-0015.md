## Causal boundary and remaining work

The first differing audit in sparse log timestamp order is HIP0 ordinal 1 (`mono_ns=15843253750062`), after identical CUDA0 ordinals 0–1 and HIP0 ordinal 0. The corresponding TSV has `target_process_begin` at 15843225093321 and `target_process_end` at 15843286915729: slot 0, verification count 0, generation count 0, batch 4, draft count 0. This is the final prompt batch immediately after the previous prefill batch ended at 32805 prompt tokens; the following first `draft_begin` is at 15843291697368. It is therefore **before first draft, acceptance or rollback**. HIP1's first difference is later in this same target batch; CUDA's first difference is in the subsequent speculative reprocessing interval. `node_2194` is a graph tensor identity, not proven to be a stable model layer; slot 0 is known but the audit stream is not itself a sequence ID. Do not infer an exact layer from node number. Sparse HIP0 ordinal 0 precedes the difference and could affect downstream selection; no matched attention output was saved, so neither sparse accumulation nor top-k sensitivity is established as the cause.

The existing comparator aligns per-device order and checks shape, not logical token identity; these runs did not save complete actual candidate IDs. Sampled output/acceptance similarity does not prove aligned teacher-forced execution. Full sequence serialization exists in `src/llama-memory-recurrent.cpp` and server checkpoint logic in `tools/server/server-context.cpp`, but a synchronized, bounded, layer-labelled recurrent-state and pre-sampling logits capture through actual acceptance/rollback was not implemented or validated. The absence of this harness, and of Q/K/V/indexer-score snapshots, is the unresolved blocker: no tolerance or numerical correctness conclusion can be justified yet. No 98K replay was attempted.

Next: instrument graph construction with stable attention layer/sequence/position labels and bounded snapshots around the first prompt-batch HIP0 masks, capturing identical-mask dense/sparse output and indexer score margins. In parallel design an opt-in token-aligned verifier harness that captures actual logits and recurrent cells at before-verification, post-commit and post-rollback/reprocess boundaries, with dense-repeat control and synchronization; validate both accepted and rejected cases. GPU replay, mixed sequences and graph-safe fail-closed overflow remain separate gates. No GitHub Actions were used.
