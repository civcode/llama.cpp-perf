## Chat AI implementation (already committed in handoff revision)

1. `tools/server/server-step-trace.h` records both `CLOCK_MONOTONIC` and nearby `CLOCK_MONOTONIC_RAW` timestamps, retaining the old TSV columns and adding `raw_ns`. It exposes `server_step_trace::flush_now()`.
2. `tools/server/server-context.cpp` writes a durable trace snapshot after the final HTTP response is queued and another after the final `post_decode_end` marker when the slot is idle. **This is disabled unless `LLAMA_SERVER_STEP_TRACE=/absolute/path.tsv` is set**; snapshots entail host file I/O only at request completion and clean exit, never additional GPU synchronization. The earlier version flushed only at process exit.
3. `docs/LLAMA-PERF/tools/server_step_trace_analysis.py` preserves optional raw timestamps in parsed and exported host windows; old TSVs without them still parse.
4. `docs/LLAMA-PERF/tools/rocpd_step_alignment.py` reads the stable ROCPD `kernels` and `regions_and_samples` SQLite views, pairs `target_sync` (or specified phase) host intervals with individually clipped Radeon GPU kernels, computes **per-Radeon busy union** and flash-attention overlapped execution, and exports per-step CSV/JSON. It supports `--clock auto|mono|raw` and a **user-calibrated** `--clock-offset-ns`; refuses clearly disjoint clocks or ambiguous automatic alignment. Its output is AMD **overlap**, not a proof of kernel dependency or an NVIDIA+AMD critical-path DAG. New synthetic unit tests live in `test_rocpd_step_alignment.py`.
5. Full mixed-GPU compilation, true clock correlation and on-device tests are **not verified by Chat AI**. The local agent owns debugging/validation now.
