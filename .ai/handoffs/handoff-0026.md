## Chat AI implementation now committed — new tools not yet locally executed

1. **docs/LLAMA-PERF/tools/generate_qsa_counterfactual_tasks.py** generates 12 version-1 compatible tasks using fixed seed20261114/520 records by default. It builds six pairs: TAG literal retrieval and exact JSON STATUS extraction for a record near the start (record 3), middle, or end (record -4) of a fictional ledger. Within each pair the **entire query is identical** and the two ledgers differ in exactly **one field of exactly one record**. Gold answers are computed from the changed source row before any inference and necessarily differ. Both A and B variants must be answered correctly to count as a pair success. The metadata includes pair_id, variant, target_band, target_id and changed_field. There is no data from the previous sample and no certified held-out claim.
2. **docs/LLAMA-PERF/tools/analyze_qsa_counterfactual_pairs.py** validates the one-field source intervention by inspecting the literal text, checking the actual changed row matches target location/ID/field and both gold values, and demanding exactly six complete pairs. It reuses strict run_qsa_quality_tasks.py result-file alignment, exact gold scoring and checks dense-repeat text/finish/prompt-token consistency and context floor. In **dense-only** mode it reports the number of pairs both of whose variants are stably and correctly solved by the baseline. --require-baseline-pair returns 2 when zero, to stop another floor-limited experiment before the sparse process. With --sparse it reports pair-level preservation/regression/improvement, and marks token-count-incomparable pairs separately, not as sparse errors. **The tool does not prove actual HIP kernel dispatch**, which still needs trace evidence.
3. **docs/LLAMA-PERF/tools/test_qsa_counterfactual_pairs.py** has 11 synthetic tests for deterministic generation, gold extraction, exactly one changed source row, location coverage, dense-only calibration, true pair changes, usage mismatches and fail-closed malformed inputs. No changes to production numerical code, server logic, graph or selector guards. The previous 103 QSA tests should still pass; these new scripts have not run on Chat AI's local GPU-less host.
4. Updated docs/LLAMA-PERF/QSA-SPARSE-TASK-QUALITY.md with Report 0025 observations and complete staged command protocol. The existing run_qsa_quality_tasks.py, score_qsa_quality_tasks.py and server request-boundary monotonic markers remain unmodified.

## Decision and boundaries

This experiment is a **synthetic, matched-data task-quality probe**, not a representative deployment benchmark and not a user-approved degradation tolerance. Even a clean 6/6 pair preservation result is insufficient for numerical equivalence or production GO. Its value is showing whether sparse preserves **conditional source grounding** under a single factual change and at varied long-context distances.

Do not change kernel arithmetic or mask layout; preserve existing HIP sparse guards, overflow fail-closed host check, model/KV precision and MTP acceptance semantics.
